# ADR-0006 — Authentication and authorization

- Status: ACCEPTED (2026-09-23, human "proceed" at Phase 1 gate)
- Date: 2026-09-22
- Spec: §25, §37 · Amendments: A7

## Context
OmniGrowth is local-first, single-tenant, multi-brand and API-only until Phase 11. §37 requires recording who made each change.

## Decision
- Local user accounts (`users`) with argon2id password hashes. Bootstrap: `poe create-owner` creates the first OWNER (no default password).
- `POST /api/v1/auth/login` returns an opaque random bearer token; only its SHA-256 hash is stored (`api_tokens`, with expiry, last_used_at, revoked_at). Scoped tokens can be minted for scripts / n8n.
- Roles: `OWNER` (everything incl. credentials, users, enabling live publishing; EDITOR may *disable* live publishing — the fail-safe direction), `EDITOR` (content, approvals, scheduling), `VIEWER` (read-only).
- No cookies → no ambient credentials → CSRF not applicable. If the Phase 11 UI adopts cookies, CSRF protection becomes mandatory and this ADR is superseded.
- Inbound webhooks: HMAC-SHA256 over timestamp + body, 5-minute window, constant-time compare.
- Rate limits per token and per IP (Redis-backed).
- Every mutating request by a user records `actor_type=HUMAN, actor_id=user.id`; webhook-triggered actions record `actor_type=SYSTEM, actor_id=webhook:<endpoint_id>`.

## Consequences
+ Simple, dependency-light, fully offline.
− No SSO / OIDC. Can be added later behind the same `current_user` dependency.

## Alternatives
- No auth on localhost: rejected by §25.
- JWT: stateless but revocation is awkward; opaque tokens are simpler here.
- OIDC via an external IdP: overkill for a local tool; possible later.
